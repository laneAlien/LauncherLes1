# Ревью репозитория LauncherLes1

---

## 🔴 Критические проблемы

**Хардкод абсолютных путей в `MGAMESpage.xaml.cs`**

Пути прибиты к конкретной машине и работать у других не будут:

```csharp
// Так делать нельзя — это работает только на твоей машине
string path = System.IO.Path.Combine(AppDomain.CurrentDomain.BaseDirectory,
    "G:\\ауе\\ПроектыВизуалСтудиё\\LauncherLes1\\...");
```

Нужно заменить на относительный путь:

```csharp
string path = System.IO.Path.Combine(
    AppDomain.CurrentDomain.BaseDirectory, "MemoryGame1.exe");
```

---

## 🟠 Серьёзные проблемы

**Неправильное использование `Path.Combine`** — первый аргумент `BaseDirectory`, второй — полный абсолютный путь. `Path.Combine` в таком случае просто игнорирует первый аргумент. Это логическая ошибка.

**`CTRViewModel.cs` — пустой класс**, подключены лишние `using`-и, файл нигде не используется.

**Опечатка в названии базового класса** — `ViewModedBase` вместо `ViewModelBase`. Имя файла `ViewModelBase.cs`, а класс внутри называется `ViewModedBase`.

## 🟡 Проблемы кода

**Все страницы создаются при запуске** — в `MainViewModel.cs` все `Page` инстанцируются сразу, даже если пользователь никогда на них не перейдёт. Лучше использовать ленивую инициализацию.

**Команды создают новый `RelayCommand` при каждом обращении к свойству** — неэффективно. Команды нужно инициализировать один раз в конструкторе:

```csharp
// Плохо (каждый раз new)
public ICommand OpenCBpage => new RelayCommand(() => CurPage = CB);

// Хорошо
private ICommand _openCBpage;
public ICommand OpenCBpage => _openCBpage ??= new RelayCommand(() => CurPage = CB);
```
